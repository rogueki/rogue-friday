# P9 Research: source-discovery checkpoint

This checkpoint adds one real, bounded search-provider path. It does **not** complete the Research family in `implementation-spec.md` §269.

- The owner configures a loopback SearXNG HTTP endpoint in Research. The Control API persists the endpoint and a revision. A staged preview binds that revision; a changed endpoint invalidates confirmation. Disabling the provider blocks new searches but does not invalidate an already recorded request receipt.
- The Research page and explicit natural-language command stage an exact topic, require confirmation and the native tier-2 policy, then persist the project and at most ten unique search results. The source records contain search-index snippets with `retrievedAt: null`, zero reliability and no findings or artifacts. The UI labels them unverified. The API never calls a result URL.
- Search requests have a 12-second deadline, a 512 KB streaming response cap and no automatic retry. Provider failure, JSON-disabled, rate-limit, timeout and restart interruption are recorded without claiming completed research. Owner-scoped reads survive reload. The request key prevents duplicate provider submission on replay.
- The existing Hermes dashboard adapter has no structured Research project/source write API. This checkpoint therefore uses a local provider and SQLite storage. The owner can now initiate a pinned local SearXNG setup from the Research page; no live search request was sent during fixture tests.

Follow-up provider choice: the owner can select the fixed English Wikipedia REST page-search endpoint from the Research screen. This works on a fresh install without SearXNG or an API key, but covers only Wikipedia, not general or current web research. The exact endpoint and `q`/`limit` parameters follow the [official MediaWiki REST search reference](https://www.mediawiki.org/wiki/API:REST_API/Reference#Search_pages). Friday sends an identifying User-Agent, caps the response like SearXNG, records the provider on each project and source, and still labels the results as unverified snippets. No live Wikipedia request was made in tests.

Page-retrieval follow-up: the same confirmed request attempts at most three result pages. A server-side HTTP client pins DNS to a checked public address, rejects redirects and non-HTML/plain responses, and caps each page with one five-second DNS-plus-download deadline and a 128 KB streaming limit. The extracted plain text (up to 16 KB), SHA-256 hash, fetch timestamp and per-source status are stored locally and shown in the source detail. Failed fetches remain visible alongside their search snippet; the project remains in review and never claims verified findings. No arbitrary result URL is fetched by the browser. Isolated local HTTP and TLS socket fixtures tested DNS pinning, Host/SNI, certificate hostname checking, redirect rejection, response size and timeout. A real public-page provider round trip remains NOT_RUN.

Evidence-draft follow-up: at most one complete, topic-matching sentence per successfully retrieved page is persisted as a source-linked **draft** finding. Its statement is copied verbatim from the stored page body, its confidence is zero, and no failed or snippet-only source yields a finding. The persisted project summary reports source/page/draft counts and explicitly says the statements are unverified. Owner-scoped finding reads survive reload; this deterministic extraction is not a model synthesis or verification step.

Native provider-setup follow-up: the owner Research screen offers a local SearXNG setup/repair button, a status refresh, Wikipedia selection and a custom loopback endpoint. Setup runs the bundled `installer/wsl/setup_searxng.sh` via the saved Friday WSL distro as root. The helper installs Ubuntu's Podman and Python YAML package when absent, pulls the official SearXNG GHCR image **by immutable digest** (`sha256:5ed0323b5f5f8701264ef65e239a2bd83cb57098f2b971fa30bf79c06eeae271`, registry manifest checked 2026-10-20), and installs a systemd service bound to `127.0.0.1:43696`. Its settings helper preserves existing YAML values and backs up the file before enabling JSON; it rejects detected concurrent edits and preserves the original file mode/owner. Readiness requires the active container's image ID to match the pinned image plus a bounded queryless JSON `/search?format=json` probe returning `400 {"error":"No query"}`. This checks JSON capability without dispatching a real search. The Control API independently probes the Windows loopback endpoint before it selects the provider. A failed setup or Windows port-forwarding failure leaves the prior provider revision unchanged; the UI shows the stopped state and allows retry. A lock prevents concurrent installs. A 300-second timeout is explicitly uncertain because a WSL child may continue; inspect status before retry. An isolated Podman-machine fixture using freshly generated settings started the pinned image and returned HTTP 400 `application/json` with `{"error":"No query"}`; its running image ID matched the pinned image ID. That fixture was stopped and removed. Runtime installation in a clean Friday WSL and an actual web search remain NOT_RUN.

The setup follows the [official SearXNG container instructions](https://docs.searxng.org/admin/installation-docker), [settings inheritance](https://docs.searxng.org/admin/settings/settings), and [JSON search API](https://docs.searxng.org/dev/search_api.html). The pinned image digest avoids a mutable `latest` deployment; updating it requires an explicit reviewed code change. Owner setup may download the image and Ubuntu package dependencies. The optional local setup is not required for Wikipedia-only searches.

Model-assisted draft follow-up: after search and at most three bounded page captures are durably saved, Friday can make one Hermes model turn through the already installed, pinned Hermes source and its configured model/credentials. Windows invokes the bundled helper through the saved Friday WSL distro; native Linux invokes the same helper directly under the running user. The Research screen links to native Hermes model/access settings and warns that this turn may cost money. The helper rejects changed Hermes source revisions, uses the empty `bot_room` toolset, disables context files, memory and background review, and limits the turn to 700 output tokens, 45 seconds of agent budget and a 55-second child deadline. It suppresses plugin discovery and left-core migrations during agent construction and rejects any nonempty effective tool surface. Captured pages enter only as untrusted data. Friday accepts at most three observations with unique saved source IDs and exact 20–500 character quotes present in the captured page text. Accepted statements form a deterministic, source-named result brief and remain unverified drafts with confidence zero; quote presence does not establish that a statement follows from the quote. The project remains `running` while synthesis is in flight; a restart marks it `INTERRUPTED` without redispatch, leaving saved sources available. If no model route is available or it returns no usable observations, source captures and local verbatim draft passages remain available with an explicit result note. A replay of the same research request does not make another model call. Fixture tests cover a valid observation, fabricated quotes, duplicates, unavailable synthesis, early helper `stdin` failure, Linux target selection, in-flight state and replay. The pinned source was probed without a provider call using a fake loopback model and temporary data root after import: `bot_room` returned `tools=[]`, `includes=[]`, and the constructed `AIAgent` had `tools=[]`, `valid_tool_names=[]`. The `_api_max_retries=1` setting is one maximum attempt in the pinned `conversation_loop.py` (`retry_count < max_retries`). **A real paid model call and clean Friday WSL/Linux end-to-end run remain NOT_RUN.**

The local implementation now has selectable SearXNG/Wikipedia search, bounded page retrieval, durable sources, source-linked draft findings, an optional Hermes model brief and bounded request/cost disclosure. It still does not verify the truth or entailment of extracted/model statements; an owner must review the cited material. Live owner-browser/provider verification, clean installer runs and an actual configured model call are outstanding acceptance evidence. Wikipedia covers encyclopedia search only; general web search requires SearXNG setup or an owner-configured compatible endpoint.

Local fixtures: focused API and UI tests, API/Web TypeScript, contracts check, ESLint and app build are the checkpoint gates. No D: installation, external call, paid provider or production round trip was performed.
