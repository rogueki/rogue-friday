# P8 agent-task model routing (synthetic acceptance)

The dashboard `modelsRouting` area now supports four task kinds: the existing three voice tiers and `agent-task`. An `agent-task` route is resolved before a direct task or text-command preview is staged. Its `provider:model` and reasoning level are bound to the saved action. An explicit per-task model or reasoning level wins. Changing the route before confirmation causes a 409 conflict; a changed route does not silently alter an approved task. A discarded preview remains discardable after a route change.

The pinned Hermes source [`d923a5e` `plugins/kanban/dashboard/plugin_api.py`, lines 367-410](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/plugins/kanban/dashboard/plugin_api.py#L367-L410) accepts `model_override`, `provider_override`, and `reasoning_effort` on Kanban POST. Its [`kanban_db.create_task`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/hermes_cli/kanban_db.py#L1080-L1113) persists those fields. The Friday Hermes adapter sends these three fields and reads the model/provider and supported reasoning level from the native task card. The task drawer displays this readback.

The Hermes Kanban endpoint has no per-task fallback field. `agent-task.fallbackModel` is rejected with 422, and the UI directs the owner to the separate global Hermes fallback configuration. The model catalog shown beside the route is a provider picker or curated candidate list; neither a successful catalog fetch nor persistence proves credentials, access to one model, or a paid inference. Voice routing remains its existing three-tier consumer. The `monthlyBudgetEur` display is still not an enforced cost limit.
