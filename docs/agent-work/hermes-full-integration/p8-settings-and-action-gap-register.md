# P8 settings and dashboard action gap register

This source audit adds field-level evidence slots to `settings-runtime-map.csv` and action families to `dashboard-coverage.csv`; `dashboard-action-nlp-coverage.csv` expands the 20 areas into reviewable action families. `SOURCE` means a source path establishes a code/schema mapping only. It does not mean the behavior passed a test. `NOT_RUN` is retained for browser/runtime, effective readback, restart, failure recovery, accessibility and NLP acceptance. The read-only validator checks CSV structure only; it cannot establish runtime correctness.

The field matrix uses the exact 12 checks from `acceptance-ledger.md` (SETTINGS-ALL-04): source of choices; effective readback including pre-existing values; type/range/dependency validation; persistent save and write-only secret handling; actual apply/restart; domain-specific observed effect; restart persistence/effect; concurrent edit conflict; separate load/save/apply/verify errors; discard/compensation; keyboard/mobile/labels/help/loading/empty-list usability; and natural-language query/setup/change. A source citation records implementation mapping only; acceptance remains `NOT_RUN` unless separately evidenced. Existing 108 field rows and legacy columns remain intact.

Source corrections:

- `theme.activeThemeId`, `theme.cyanIntensity`, `theme.panelOpacity`, and `theme.goldIntensity` map to the live `AppSettingsProvider` apply effect in `apps/web/src/lib/settings.tsx` (`runtimeThemeSettings`, `applyTheme`). Browser style/readback and restart tests remain `NOT_RUN`.
- Orb fields map through `orbSettingsFromWire` in `apps/web/src/features/orb/OrbSlotInner.tsx`; motion mode also applies in `apps/web/src/lib/settings.tsx`. A static name miss was not treated as a missing consumer. Visual behavior tests remain `NOT_RUN`.
- `dashboard.location.countryCode` is location-selection/display metadata; weather behavior consumes the stored coordinates. `version` and `updatedAt` are server metadata, not editable settings.
- `dataRetention.memoryDefaultTtlDays` is explicitly constrained to `null` by `SettingsService.assertReferences` and disabled in the UI; non-null expiry is intentionally unsupported.

Concrete local implementation gaps supported by source:

- Voice UI exposes `wakeWordEnabled`, `wakeWord`, `pushToTalkKey`, `speakerVerificationRequired`, `voiceHistoryEnabled`, `storeRawRecordings`, and `ttsRate`. The settings handler's explicit apply/rollback branch is limited to voice persona and input/output audio devices (`apps/control-api/src/handlers/settings.ts`, lines 315–364). No per-field update bridge/acknowledgement was found for the seven settings. These values can be persisted without evidence that the active voice service changes behavior.
- `voice.storeRawRecordings` is especially misleading: the settings UI permits true, while `adapters/voice-http/src/mapping.ts` reports `rawRecordingEnabled: false` and states the service never stores raw audio. The control should be explicitly unsupported/read-only or connected to an implemented storage behavior with accurate privacy disclosure; do not claim current recording behavior from the setting value.
- `voice.voiceHistoryEnabled` is likewise presented as editable while `adapters/voice-http/src/mapping.ts` hardcodes `voiceHistoryEnabled: true`. No handler gating of history reads/writes by this setting was found in the scoped source search. A local fix should either make the setting effective end-to-end or represent it as unsupported until that can be done.
- `voice.inputDeviceId` and `voice.outputDeviceId` do have apply/rollback and status acknowledgement code plus focused service tests. Physical device selection and audible/microphone effect remain hardware `NOT_RUN`; these are not classified as absent local consumers.
- Notification `channels[].accountId` accepts arbitrary text in `apps/web/src/features/settings/BasicAreas.tsx`; no selected-account catalog binding was found in the scoped control API path. A safe local task is to bind it to a verified account catalog or restrict it to the supported default value while preserving unknown existing values visibly.

Dashboard/NL interpretation:

- Native UI/API capability is kept separate from natural-language command parsing. Each action row now names the HTTP operation or local UI operation, its specific parser intent when present, or `NOT_MAPPED`; the exact UI callback remains `NOT_VERIFIED` when the area source alone cannot establish the binding. This avoids treating an area's mutation handler as the action for its read/navigation controls. NLP-01..06 acceptance remains `NOT_RUN` pending the dedicated NLP worker.
- Automation creation remains a structured form operation because trigger/condition/action structures should not be invented from an underspecified utterance (`p9-automation-actions.md`). Device enrollment/audio checks, account credentials/provider setup, and external delivery are explicitly marked as physical/external steps where relevant.
- At `f570014`, ResearchPage selects existing projects and sources and exports Markdown/JSON. `apps/web/src/lib/api/domains/research.ts` exposes only GET queries; the OpenAPI route `/api/v1/research/projects` is GET-only even though the example advertises `research.create=true`. There is no create-project or add-source UI/API operation in the inspected source. This is a concrete contract/consumer gap. Research NLP stays `NOT_RUN` while Research Sol works independently; no result is assumed or copied into this matrix.
- A concrete dashboard gap family is content-studio: UI exposes key setup, generation/media/workspace actions, but the contract example and command intent family do not establish a corresponding NL action consumer. `dev/scenarios` is intentionally mock-only and should not gain a live NL action; scenario controls must remain gated. For the remaining areas, the matrix gives action-family-level native/NL evidence and does not count every `UNMAPPED` legacy cell as a defect.
