## How to use the inventories

The Hermes JSON has 2,522 candidate records across overlapping kinds: 814 config leaves, 153 optional environment variables, 153 optional skills, 58 bundled/locally present installed skills, 102 plugin manifests, 614 plugin-catalog offerings, and 2 locally installed plugins at the recorded snapshot. Those are source rows, not 2,522 capabilities. In particular, a catalog plugin is not installed or active; `optional_skill` is not bundled; `installed_skill` still does not prove its tools/dependencies are usable. Before exposing a control, P7 must enumerate the effective Hermes revision, enabled plugins/skills, environment/config overlays, host/platform support and credential state on the target. The enumerator must label `installed`, `enabled`, `configured`, `authenticated`, `available`, `needs_setup`, `unsupported` and `unknown` separately. Do not write all 814 defaults into forms or treat absence of a search hit as proof of no indirect consumer.

The P0 Friday map is also a static candidate map, not acceptance evidence. Existing `SettingsService.patch` persists an entire settings area in SQLite and bumps its optimistic version (`apps/control-api/src/services/settings.ts:383-410`). Generic `PATCH /settings` therefore proves storage only. P1's persisted/applied/verified status and revision contract is a prerequisite to green states. Each field bundle must retain the existing `If-Match` behavior and use typed, discoverable choices; raw JSON may remain an expert import/export tool but cannot be the normal setup surface.
