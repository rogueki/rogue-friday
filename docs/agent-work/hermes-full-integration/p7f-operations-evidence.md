# P7-F source and operation evidence

The pinned source is `d923a5eb487a17c0a68801bba9ef0f56c81040a8`. `p7f-config-coverage.json` contains all 75 config inventory leaves in `cron.*`, `gateway.*`, `logging.*`, `monitoring.*`, `updates.*`, and `hooks_auto_accept`. This is the same denominator as the D/F union checkpoint: 67 in the first four families plus eight update/hook policy keys. Its test rejects a missing or new leaf, mismatched source provenance, or a typed key that differs from the bridge allowlist. The 18 exposed controls use the Hermes config CLI with revision conflict and readback. That confirms persistence, not an active scheduler/gateway reload; no live Friday runtime was changed for this slice.

The nine cron controls have source consumers in `cron/jobs.py`, `cron/scheduler.py` or `cron/scheduler_script.py`. Their owner is the Hermes profile scheduler, not Friday Automations. A cron job's schedule and timezone remain native job data; these config controls do not create jobs or change a job timezone. The six gateway controls feed `gateway/run_startup.py`, `gateway/run_shutdown.py`, `gateway/run_config_loaders.py` or `hermes_cli/gateway.py`; changing them in `config.yaml` requires a separate effective process-state check. The three logging controls are read by `hermes_logging.py:957-977` and applied to `agent.log` in `setup_logging()` at `hermes_logging.py:326-400`. Native callers include `agent/agent_init.py:721`, `cron/scheduler.py:4431` and `gateway/run.py:5181`. The isolated pinned-source fixture `test_hermes_logging_runtime.py` proved `DEBUG`, 7 MiB and four backups on the actual queued rotating handler. An already running process keeps its initialized handlers; the field metadata therefore states that a new process is required. Hermes uses `backup_count or cfg_backup or 3`, so zero would silently become three: writes now require at least one. A pre-existing zero can still be read back and should be corrected by the owner; readback alone does not mean zero is effective. This fixture did not change or test the live Friday install.

Native operations remain open. `hermes_cli/subcommands/cron.py` offers `list`, `create`, `edit`, `pause`, `resume`, `run`, `remove`, `status`, `runs`, `incidents`, `doctor` and `tick`, but its output is human-oriented and it does not expose a JSON flag in the inspected parser. A safe Friday task/schedule action needs typed job IDs, owner/profile/timezone, native store reconciliation, and a staged approval/receipt before any mutation. `hermes_cli/subcommands/hooks.py` offers inspection and actions; a hook test executes code and cannot be treated as read-only. `hermes_cli/subcommands/update.py` has read-only check/plan paths; applying an upstream update must preserve the pinned Friday Hermes patches or fail closed. Gateway service restart/status require an actual process and service-manager postcondition. Monitoring export needs endpoint and privacy validation plus an effective telemetry check. None of these is claimed complete by typed config readback.

The current P7-F blocker for final acceptance is runtime evidence: an isolated clean install must prove supported settings affect the native consumer after the correct restart, scheduler status and job ownership match the chosen profile/timezone, and the desired native operations are implemented with typed, safe APIs. Natural-language P7-F actions are not wired yet. New Hermes versions must be diffed against the 75-leaf matrix before exposing their fields.
