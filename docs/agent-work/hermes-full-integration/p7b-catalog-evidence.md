# P7-B provider catalog checkpoint

The owner-only `GET /api/v1/settings/hermes-model-catalog` loads the provider IDs and labels from the installed pinned Hermes picker's `listed_canonical_providers()`. It does not query a provider. `providerListComplete` remains unknown because Hermes plugin-profile discovery may fail silently. The config status lists only configured profile IDs and marks that list incomplete.

With an explicit `providerId`, Friday runs a bounded Hermes child in a separate process group. Only `openai-api` and `anthropic` use pinned Hermes catalog fetchers for an endpoint query. Other providers expose pinned curated candidates and `probeStatus=unsupported`. A failed endpoint query also returns curated candidates with `probeStatus=failed`. An endpoint response is labelled `endpoint_confirmed_picker`; some picker rows may still be curated and `modelAccess` remains unknown. The action never issues model inference, assumes authentication from a stored key, or marks a live Hermes process as reloaded.

The bridge checks source revision `d923a5eb`, validates the provider ID and projects only catalog fields. The Control API again validates and projects the payload. Runtime child timeout kills and waits for its process group before the Friday config locks are released, to prevent a delayed credential writer from committing after an apparent timeout. The pinned [`runtime_command`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/hermes_cli/_launchers.py#L33) launches Python directly; pinned [catalog selection](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/hermes_cli/models.py#L1366) and [credential lifecycle](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/hermes_cli/credential_lifecycle.py#L149) determine the boundary.
