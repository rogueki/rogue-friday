# P3 Obsidian memory: implementation and operating notes

## Current paths and data authority

`installer/setup-obsidian.ps1 -Action ensure -InstallRoot <root>` creates or preserves the selected Windows vault. The default is `<InstallRoot>\memory\Friday`. It checks a Unicode-capable Windows file round trip, maps the same path into WSL, tests WSL read/write, configures Hermes `OBSIDIAN_VAULT_PATH`, and checks the gateway restart. The selected Windows path is saved in `<InstallRoot>/config/obsidian-vault-path.txt` for the Control API after restart. The installer invokes this after Hermes setup. Existing `.obsidian` settings and notes are left intact. Changing the Vault in Settings preflights and copies Friday notes without overwriting conflicts, then switches the local writer after Hermes confirms apply. The Obsidian window is not needed for Friday's file writer. Application installation uses `winget` only when no Windows installation is found; no Obsidian Sync subscription is needed. See [Obsidian's installation guide](https://obsidian.md/help/install) and [Microsoft's winget install reference](https://learn.microsoft.com/en-us/windows/package-manager/winget/install).

The durable outbox is `<dataDir>/memory/outbox.sqlite` with WAL and full SQLite synchronous mode. Only eligible, sanitized IntegrationEvents reach it. Private and `do_not_store` events are not inserted. The Vault has one human-readable note per event under `Conversations/YYYY/MM/`. The event ID is the idempotency key. A single service writer fsyncs a temporary note, then creates the final filename atomically without replacing an existing Obsidian edit. Write failures keep the event pending. The API status reports pending count, last error, latest write, index state and latest successful isolated restore test.

The Windows voice process has its own delivery spool at `<InstallRoot>/dashboard/data/voice-memory.sqlite`. It sanitizes and commits a verified utterance or response before making an HTTP delivery attempt. A read-only check of the API's persisted capture settings gates both enqueue and delivery; missing, invalid or unreadable settings block capture, and a disabled channel or private mode purges buffered events. Private events are excluded before the spool. Failed HTTP requests remain queued for a later attempt or restart; a matching API acknowledgement deletes the local copy. This spool is separate from the API outbox so loss of the API connection does not lose an already captured voice event. It stores text after conservative credential redaction, so the file and backup policy must treat it as personal data.

The Vault is the content source. Search re-reads changed Friday notes, keeps identity boundaries, and refuses retrieval when a Friday note is malformed, unreadable or contains credential-like text. A missing committed note in an otherwise healthy complete scan is tombstoned and never silently recreated, including after API restart. An unavailable Vault or incomplete scan reports an index error without treating unseen notes as deleted. Unrecognized personal notes outside the Friday note format are untouched. A correction inserts a replacement event and tombstones the original in one SQLite transaction. Forgetting tombstones the ID and queues physical file removal; retry clears pending work. Tombstones prevent reimport. Raw audio is never used as memory input.

Native Memory settings expose a global capture switch, private mode, per-channel Dashboard/voice/Hermes CLI switches, the explicit unlimited retention policy, recognized exclusions, index status/rebuild, Vault path, backup and isolated restore test. Switching private or disabling a channel removes still-pending eligible API events for that scope; written Vault notes remain until explicitly forgotten. The `ready` status describes writer/index health only. A successful isolated restore has its own timestamp; neither that timestamp nor a live Obsidian application is implied by writer readiness.

## Backup and restore

`POST /api/v1/integrations/memory/backup` first flushes pending work and validates the complete Vault index and each note. It publishes a snapshot with SHA-256 hashes and tombstones under `<dataDir>/memory/backups/`; incomplete staging directories do not count as backups. `POST /api/v1/integrations/memory/restore` accepts only these backup directories and a new target under `<dataDir>/memory/`. It verifies every note and checksum before copying, creates a separate `.obsidian` vault, builds a separate SQLite index, and records the successful restore time. The live Vault and outbox are not replaced. Review the restored Vault before any cutover. A backup predating a forget operation may still contain the old content; handle backup retention and deletion requests explicitly.

## Coverage and evidence limits

Dashboard command input and response are captured through the native API. Voice capture and pre-answer retrieval use the scoped voice bridge path when its worker wiring is installed and verified. Standalone Hermes CLI has a pinned plugin (`d923a5eb487a17c0a68801bba9ef0f56c81040a8`) using `pre_llm_call`/`post_llm_call`: eligible owner CLI turns are sanitized into a local SQLite spool before delivery; prior matching memory is fetched as bounded, explicitly untrusted context. A separate local bridge key, CLI-only scope and persisted privacy policy gate the plugin. The installer refuses unrecognized Hermes revisions or changed hook sources. The updater stages the Git-verified bridge helper, snapshots Windows installer files and Hermes plugin/config/key, then rolls back both on failure; the first upgrade can bootstrap through the verified voice helper. Native messenger remains unlinked pending sender identity proof. Existing historical dialogue is not fabricated or imported without a real source archive. No clean-host Obsidian/WSL installation, physical microphone session, power-cut simulation or external messenger acceptance was run in this worktree.

The focused service and handler tests cover retry after missing Vault, restart, duplicate delivery, privacy redaction, identity boundaries, edited-note reindex, correction/tombstone, abort outcome, backup integrity and isolated restore. A verified voice transcript privacy request now keeps the remaining spoken session private, purges still-buffered events from that session, and excludes assistant replies. A pre-existing restore index is rejected before staging and remains byte-for-byte unchanged. Already delivered earlier session events cannot be retroactively removed by the spoken switch; use explicit forget for those IDs. These local tests do not constitute live Windows/WSL migration evidence.
