# P9 agent action family slice

The agent mutation family (agent pause / resume / stop, task assignment and coding-run stop) now runs through the same native staged pipeline as the task, calendar, mail and messenger families — no contract or OpenAPI change was needed. The previously port-backed pass-through routes `POST /api/v1/agents/{id}/pause|resume|stop` and `POST /api/v1/tasks/{id}/assign`, plus the previously direct `POST /api/v1/coding-runs/{runId}/stop` (the old one-shot handler in `handlers/skills.ts` is gone), stage the exact write first: the initial request answers `403 APPROVAL_REQUIRED` with `stage: preview`, a `previewId` and a German `previewText`; the repeat must carry the unchanged action plus `X-Action-Preview-Id`. Under the captured tier-2 policy the confirmed request either returns `stage: approval` with an approval ID for the existing decision UI, or executes exactly once and returns the entity (agent, task or run) when approval is disabled. A replayed confirmation answers the stored receipt without a second port call — replay-included for pause and assignment, where a real second write would fail the lifecycle rules.

Guards run before anything is staged: the lifecycle rules mirror the agents port (pausing needs live work, resuming needs a paused agent, stopping needs active work) and fail 409 on a drifted status, unknown agents fail 404; an assignment refuses finished tasks 409 and answers an unknown agent as 422 exactly like the wire contract of the port; a terminal or unknown coding run fails 409/404; a missing capability (`agents.pause`/`resume`/`stop`/`assignTask`) fails 403 `CAPABILITY_MISSING`. None of them leaves a draft behind (asserted against `native_approval_requests`). The port re-checks the same rules at dispatch with the pipeline's idempotency key, so a drifted state can never apply twice.

`NativeExecutableAction` gained the kinds `agent.pause`, `agent.resume`, `agent.stop`, `agent.assign` (task id plus the exact `TaskAssignRequest` body) and `codingrun.stop` in `services/native-approval-requests.ts`; the receipt sentences are `Agent <id> pausiert./fortgesetzt./gestoppt.`, `Aufgabe <id> zugewiesen.` and `Coding-Lauf <id> abgebrochen.`. `handlers/approvals.ts` dispatches all five kinds on the decision's own idempotency key: lifecycle and assignment through the agents port, coding-run stop through `runtime.codingRuns.stop`. The dev scenario reset clears staged agent drafts like every other family (tested: a confirmation after the reset fails 409).

The command path parses German agent intents in `services/agent-action-intent.ts`: lifecycle imperatives ("Pausiere den Recherche-Agenten", "Halte den … an", "Leg den … still", "Lass den … (weiter)arbeiten/weitermachen", "Setz den … fort", "Starte/Aktiviere den …", "Stoppe/Beende den …", "Fahr den … runter"), assignments ("Weise die Aufgabe <Titel> dem … zu", "Gib die Aufgabe <Titel> an den …", "Lass den … an der Aufgabe <Titel> arbeiten") and coding-run stops ("Brich den (laufenden) (Coding-)Lauf/Run ab", "Stoppe/Beende den (laufenden) Coding-Lauf/Run"). A lifecycle reference must visibly contain the word "Agent" — "Pausiere die Musik" or "Stoppe den Countdown" are never agent actions and fall through to the other parsers. A spoken agent resolves ONLY against the live registry list: exact squashed name (umlauts folded, "-Agent"/"-Agenten" suffix tolerated), zero matches 404, several 409 — an action on a guessed agent is never staged. Assignment task refs reuse the existing `resolveTaskRef`; a spoken coding-run stop requires exactly one selected run id from the command `context.selectedIds` and asks 422 otherwise. The dispatch chain slots the agent parser before messenger and mail; dismissing the preview cancels the server draft, and the confirmation binds the exact stored action, so a tampered repeat fails 409.

Web: `features/agents/useAgentCommands.ts` runs pause/resume/stop through the shared `useRunStagedWrite` runner — the server preview in the shell `StagedWriteConfirmHost` is the binding confirmation on top of the drawer's own stop check. `features/tasks/taskWriteRunner.tsx` gained an `assign` kind: the agents-port assignment is a staged write now (If-Match and body captured in the send closure; tasks, overview and agents queries invalidate on execution), adapters without the assign operation keep the staged update fallback. `features/skills/CodingRunsArea.tsx` stops a run through the same runner. The now-dead direct mutation hooks `useAgentAction` (domains/agents) and `useAssignTask` (domains/tasks) were removed like in the earlier waves. Component tests drive the staged flow (first call without, repeat with `X-Action-Preview-Id`); the e2e agents spec confirms pause, stop and assign against the real stack, each waiting for the server preview before anything executes.
