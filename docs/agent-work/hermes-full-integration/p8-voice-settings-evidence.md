# P8 Voice settings runtime evidence

Scope: isolated synthetic fixtures only. No installed voice service, microphone, user recording, or live Friday state was changed. The existing uncommitted Automation worktree was not touched.

Wake-word changes now use the owner-authenticated browser enrollment flow. Phrase-bound PCM samples stay in a private staging directory. A bounded asynchronous worker trains the model; status polling reports counts, quality and errors, and the owner may retry or discard. Training never activates a model. Only a later explicit settings save loads the candidate and applies it with the observed runtime revision. A stale revision, busy service, failed training or discarded job leaves the active model unchanged. Cancellation and restart clean private staged audio and uncommitted models.

The dashboard update and voice-persona payloads include `runtime_settings.py`, wake trainer and its source dependency in the pinned payload. The voice process publishes a configuration revision and requires the caller's observed revision and process identity on settings apply. Its settings, persona, and device writes share the process lock. The Control API applies before committing settings, checks process identity and readback, and rolls back runtime settings only against the revision it demonstrably wrote. A narrow race with a non-cooperating external file writer between final hash check and replace is still possible; there is no cross-process lock for arbitrary editors. Voice-history outbox purge occurs only after the configuration commit; a purge failure leaves capture/delivery disabled and is logged for retry by the worker.
