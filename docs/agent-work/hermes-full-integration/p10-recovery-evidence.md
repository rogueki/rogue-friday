# P10 isolated operational recovery — implementation evidence

The recovery target must be a separately completed Friday installation using the same dashboard build, a distinct WSL distribution and the same Linux username. The target Control API must contain no owner or application data; first-boot built-in library rows and `hub.sequence` are allowed. The Obsidian Conversations directory must be empty. Recovery never writes to the backed-up installation or Vault.

`SystemBackupService` records its source install root and Vault path. `SystemRecoveryService.prepare` verifies the complete P8 backup, audit anchor, Memory index and WSL manifest, checks the fresh target, remaps installed Windows paths and ports, and creates private staged files with exact before/after hashes. `apply` refuses changed targets or pending SQLite WAL. Its journal supports rollback after an interrupted move and refuses to overwrite data changed after activation.

The WSL importer requires a clean checkout at the backed-up pinned Hermes revision. It keeps exact private baseline copies of already provisioned profile files, journals before replacement, verifies the imported hashes and restores unchanged baselines on rollback. It preserves the fresh profile's unrelated files. A stale Messenger bridge apply marker is discarded so the restored gateway reapplies the scoped key.

`installer/scripts/recover-friday.ps1` provides the target-only orchestration: stop owned scheduled tasks and the target Hermes services, prepare, import WSL state, apply Windows state, run the target installer in `-UpdateDashboard` mode to reprovision the Hermes bridges, then check the dashboard HTTP health and active Hermes gateway. It validates a DPAPI-bound ElevenLabs key before import. Failure attempts WSL and Windows rollback; if an installer or service has changed recovered data, rollback refuses and retains the private staging and receipt for diagnosis. This is a deliberate no-data-loss boundary, not a promise of unconditional rollback after startup writes.

Verified in isolated fixtures: API backup/recovery tests (23 passed), WSL import tests (8 passed, including existing-file replacement, interrupted receipt, SQLite sidecars and changed-file refusal), API typecheck and focused lint, production API build with recovery CLI, PowerShell parser and an isolated PowerShell fault harness. The harness injects a foreign task, partial task-disable failure, prepare failure, malformed WSL receipt response, Windows apply failure, installer failure and health failure; each path checks rollback and original task-state handling. A hybrid/local Control API was started and stopped against a temporary profile; its actual first-boot SQLite was accepted by the fresh-target guard. The transient Hermes Yuanbao Unix socket is excluded by the WSL socket filter and must be recreated on gateway restart. No live `D:\Kali\Friday` installation, existing Friday WSL distribution, credentials, provider account, or physical voice device was modified or probed.

Open acceptance gates: a clean isolated Windows/WSL installation followed by an end-to-end recovery and service health run; verification of each scoped bridge's functional API path after reprovision; cross-Windows-user cloud voice requires re-entering the DPAPI-bound ElevenLabs key. The PowerShell fault harness uses mocked scheduled tasks, WSL calls and installer results; physical scheduled-task and WSL behavior remains unverified. A backup from an earlier build without source-path metadata cannot enter this operational import, but remains valid for P8 inert verification.
