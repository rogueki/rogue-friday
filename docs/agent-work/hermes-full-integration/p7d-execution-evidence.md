# P7-D execution controls checkpoint

Friday exposes three pinned Hermes config leaves as typed owner-only writes with revision checks: `terminal.timeout` (1–3600 seconds), `browser.command_timeout` (5–600 seconds), and `browser.snapshot_threshold` (1,000–200,000 characters). The installed Hermes `config get` readback proves persistence only. Friday marks each runtime verification `unverified` because running terminal children and browser modules can retain previously resolved values; browser values are process-cached. Source: [terminal config-to-env bridge](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/hermes_cli/config.py#L2100), [terminal tool consumer](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/tools/terminal_tool.py#L743), [browser cached consumers](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/tools/browser_tool.py#L201).

P7-D extension (2026-10-20): The typed owner/CSRF/If-Match route now also reaches the pinned native terminal backend and cwd, Docker network/workspace mount/volume controls, private browser URL and real-profile consent, profile pin and evaluate policy, code-execution mode, Computer Use standard/bounded permission and manifest, global toolsets, approval mode/timeout, and removal of existing command allowlist entries. The bridge validates these independently of browser input before Hermes' native `config set`, then reads back each leaf. Docker options require the Docker backend; switching to Docker requires network to be explicitly disabled, no mounts, and a responding daemon. Host workspaces and volume sources must be existing directories under the WSL user home but outside `~/.hermes`; container mount targets are confined to `/workspace/mounts/<name>`. A bounded Computer Use mode requires a manifest path; the manifest must be a regular file under `~/.hermes` and cannot be removed while bounded mode is active. Real-profile consent requires a pinned profile directory name to avoid selecting a different last-used identity. `unrestricted` is rejected. Toolsets must exist in the installed Hermes `TOOLSETS` registry. Friday never adds permanent command approvals through direct config writes: the allowlist editor can only remove existing entries, leaving additions to Hermes' human approval flow. `approvals.mode: off`, unattended auto-approve, and disabling protected instruction-file approval are rejected. Incompatible `browser.restrict_evaluate` and `browser.allow_unsafe_evaluate` values are rejected. Disabling real-profile consent removes the local Hermes credential-snapshot directory immediately and returns an error if cleanup cannot be confirmed.

These are real Hermes configuration consumers for future terminal, Docker, browser, code kernel and Computer Use sessions. Status still says `unverified` for running-session adoption; no command, browser navigation or desktop action is executed by this settings route. A fresh clean-install runtime acceptance run remains necessary, especially for Docker availability, Windows-to-WSL browser profile access and profile-snapshot revocation. No live Hermes profile was changed during implementation.
