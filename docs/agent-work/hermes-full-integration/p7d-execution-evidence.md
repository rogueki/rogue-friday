# P7-D execution controls checkpoint

Friday exposes three pinned Hermes config leaves as typed owner-only writes with revision checks: `terminal.timeout` (1–3600 seconds), `browser.command_timeout` (5–600 seconds), and `browser.snapshot_threshold` (1,000–200,000 characters). The installed Hermes `config get` readback proves persistence only. Friday marks each runtime verification `unverified` because running terminal children and browser modules can retain previously resolved values; browser values are process-cached. Source: [terminal config-to-env bridge](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/hermes_cli/config.py#L2100), [terminal tool consumer](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/tools/terminal_tool.py#L743), [browser cached consumers](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/tools/browser_tool.py#L201).

Host execution grants, Docker network/mounts, private browser URLs, real browser profile, unsafe evaluate, code execution, and toolsets remain outside the write allowlist. These require separate permission and runtime-adoption proofs; a config write must not bypass Friday approvals. No live Hermes execution or browser session was started in this checkpoint.
