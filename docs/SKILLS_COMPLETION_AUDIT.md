The public beta release is valid for the working core. The original full onboarding/integration objective remains active until the partial and incomplete rows have adequate implementation and evidence. Paid media generation, account credentials, calling and external publishing are excluded from acceptance probes unless explicitly needed and authorized.

Hermes key form implementation check: isolated WSL helper test covers save, removal, unrelated `.env` entries, mode 0600, allowlist rejection and absence of values from output. Focused API tests cover owner, viewer, anonymous and CSRF responses with a fake runner; no real provider credentials were used and the installed Hermes `.env` was not changed. A stored key is only a presence signal; the gateway restart result is returned for mutations and `null` for a status read.

First-owner login navigation: a focused component reproduction showed both `/onboarding` and `/` redirects after account creation because the login mutation updated session state before its success callback routed to onboarding. `LoginView` now routes once to home when the authenticated session arrives; the dashboard offers onboarding in a nonblocking popup. The two focused component scenarios and web typecheck passed. This does not replace an authenticated browser acceptance of the complete wizard.

Coding CLI beta: the owner dashboard has `auto|codex|opencode|claude-code`, selected Git root, task, status and stop. Friday launches the exact native WSL CLI with fixed argv and the validated Linux-Git root; it does not use Hermes `/v1/runs` as an advisory prompt. The runner limits work to one active job, 900 seconds and 1 MiB output, stores private run metadata, and stops its process group. Fake CLI integration tests verified selected argv, cwd, task, status, replay and process-group stop without a provider call. The targeted D: update after `46c1626` exited successfully; dashboard health, Skills page, Hermes dashboard and voice returned HTTP 200. The installed runner probed Codex 0.163.0 against a normal temporary Git repository, and an unauthenticated API POST returned HTTP 401. This repository's Windows worktree metadata is not readable by WSL Git and is rejected as a target. No real provider login or paid coding task was invoked. The new voice flow requires a saved owner alias with revision, explicit CLI and task, and a second speaker-verified confirmation within 90 seconds after the full readback. Saving the alias rejects a Git root unreadable by Friday-Ubuntu without starting a CLI or model. The voice bridge can read that alias and submit only its current revision; it cannot modify the alias. Targeted API and synthetic voice tests passed. The voice path was deployed to D:; dashboard, Hermes and voice returned HTTP 200 and voice reported `listening`. A microphone command and a provider model run remain unverified.
